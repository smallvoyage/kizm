# Apple Watchで今日の食事を確認する

iPhoneで作成したショートカットをApple Watchから実行し、今日の摂取カロリー・PFCと目標までの残量を表示します。専用アプリやApple Developer Programへの登録は不要です。

## サーバーの設定

1. パスワードマネージャーなどで十分に長いランダムな専用トークン（32バイト以上を推奨）を生成します。
2. デプロイ先に `KIZM_SHORTCUT_TOKEN` を設定し、再デプロイします。ローカルでは `.env.local` に設定します。値をGitへコミットしないでください。
3. 既存のNotion設定に加え、Daysへの接続が有効であることを確認します。このAPIではWorkoutsを取得しません。
4. WatchからアクセスできるHTTPSの本番URLを使用します。デプロイ保護によるログイン画面が出るURLでは動作しません。プレビューの保護解除ではなく、利用可能な本番URLを選んでください。

トークンはこの読み取りAPI専用です。Notionトークンをショートカットへ入れないでください。トークンを変更して再デプロイすると、古いトークンを失効できます。ショートカットに保存した値は編集画面から見えるため、他人に共有する前に削除してください。この認証は既存Webページ全体を保護するものではありません。

## ショートカットの作成

1. iPhoneの「ショートカット」で新規作成し、名前を「KIZM 今日の食事」にします。
2. 「URL」に `https://<kizmのドメイン>/api/nutrition/today` を設定します。
3. 「URLの内容を取得」を追加します。方法は `GET`、ヘッダー名は `Authorization`、値は `Bearer <専用トークン>`（Bearerの後ろに半角スペース）です。
4. 「辞書の値を取得」で、取得結果の `displayText` を取り出します。
5. 「アラートを表示」を追加します。タイトルを「KIZM」、メッセージを取り出した値に設定し、キャンセルボタンは無効にします。
6. ショートカットの詳細で「Apple Watchに表示」を有効にします。
7. 最初にiPhoneで実行して通信の許可を確認し、その後Watchのショートカットアプリから実行します。

アクション名や配置はOSのバージョンで異なる場合があります。Watchで表示される文章はスクロールして確認します。通信失敗やHTTPエラーでショートカット自体が停止した場合は、接続・URL・トークンを確認して再実行してください。HTTPエラー時に辞書を受け取れる環境では `displayText` にエラーの説明が入ります。オフライン表示や自動更新、文字盤への数値の常時表示には対応していません。

Appleの参考資料：[Watchでの実行](https://support.apple.com/en-mide/guide/shortcuts/apd5888b0858/ios)、[Watchでのアラート表示](https://support.apple.com/en-mide/guide/shortcuts/apd081d9d61f/ios)。

## 表示とデータの扱い

- 日本時間（Asia/Tokyo）の今日の記録だけを取得します。昨日以前の値では補いません。
- 目標は `lib/nutrition-goals.ts` の既存設定と共通です。
- 未入力は「記録なし」、0は摂取量ゼロです。残量が負なら「超過」、0なら「目標達成」と表示します。
- `complete` は4項目すべてに数値があるという意味で、食事の記録完了や目標達成を意味しません。
- APIと当日のNotion取得はキャッシュしません。毎回、実行時点でNotionから読める値を返します。NotionのRollup反映には時間差があり得ます。
- 「取得」は取得完了時刻で、食事を記録した時刻ではありません。
- 同じ日付に複数の有効なDaysレコードがある場合は、誤った合算や任意の選択を避けて取得エラーにします。Daysは1日1レコードにしてください。
- fixtureは固定日付のデータです。実行日の記録がなければ「今日はまだ記録がありません」になります。APIには日付の上書きパラメーターを設けていません。

## API

`GET /api/nutrition/today`、認証は `Authorization: Bearer <専用トークン>`。
すべてのレスポンスに `Cache-Control: private, no-store` を設定します。

成功例（数値は例）：

```json
{
  "date": "2026-09-19",
  "status": "complete",
  "metrics": {
    "calories": { "consumed": 1450, "goal": 1800, "remaining": 350 },
    "protein": { "consumed": 85, "goal": 140, "remaining": 55 },
    "fat": { "consumed": 40, "goal": 50, "remaining": 10 },
    "carbs": { "consumed": 150, "goal": 200, "remaining": 50 }
  },
  "fetchedAt": "2026-09-19T09:35:00.000Z",
  "displayText": "今日の食事 (2026-09-19)\n\nカロリー 1,450 kcal\n残り 350 kcal\n\nP 85 g\n残り 55 g\n\nF 40 g\n残り 10 g\n\nC 150 g\n残り 50 g\n\n取得 18:35"
}
```

`status` は `complete` / `partial` / `empty`。未入力の `consumed` と `remaining` は `null` です。記録なしもHTTP 200で返します。認証失敗は401、サーバーのトークン未設定は503、データ取得失敗は502で、`error` と `displayText` を返します。SDKエラーや秘密情報は返しません。

## 実機での受け入れ確認

デプロイとショートカット設定後、次を実際のApple Watchで確認してください。

- 当日の摂取量・残量がNotionと目標設定に一致し、末尾までスクロールできる。
- Notionの値を変更し、Rollup反映後に再実行すると数値が変わる。
- 未入力、摂取量0、目標超過が区別される。
- 当日の記録がない場合に昨日の値が出ない。
- 誤ったトークン、通信不可の場合に成功した数値として表示されない。

Web UIは変更していません。APIと表示文の自動テストとは別に、Watch固有のレイアウト・通信・許可ダイアログはこの実機確認が必要です。
